# Architecture Decision Records

**ADR-001: React + Vite + TypeScript.** Chosen for reusable UI, testability, offline static builds and contributor ecosystem. Tradeoff: dependency size and modern Node requirements. React isn't used in the keystroke hot path.

**ADR-002: Feature-first directory and dependency-inverted domain.** Code is organized by product workflow, with reusable lower-layer contracts for teaching, metrics, and persistence. Avoids giant components and a premature monorepo.

**ADR-003: IndexedDB via Dexie.** Transactional storage for sessions and skill stats. Storage remains best-effort; export/import and persistent-storage requests are future work.

**ADR-004: Hash-based routing.** GitHub Pages deep-link reload works without a dedicated server. Tradeoff: less elegant URLs, acceptable for a PWA.

**ADR-005: Local-first without registration.** No server is required for typing or lessons; community features are optional adapters, not global prerequisites.

**ADR-006: Versioned metrics.** Every historical result references a scoringVersion, layoutId, locale, content ID and mode to avoid quietly changing past performance comparisons.

**ADR-007: Transparent stages.** Stage-4 implements real measurement and skills but cannot claim a full educational corpus, audited offline installability or empirically validated adaptation until verified. No artificial user scores.

**ADR-008: UI heritage.** Stage-2 CSS is initially migrated as a visual baseline; iterative extraction to CSS Modules should preserve screenshots, token semantics and a11y.

**ADR-009: Preserve native composition.** Use native textarea value and composition-end commits for actual characters, `KeyboardEvent.code` only for non-text physical-key hints.

**ADR-010: Calibrated language.** Skill confidence is a heuristic evidence weight; no validated probability claim.

**ADR-017 (iteration 5, provisional): Bounded imperative typing window.** Native textarea and the unchanged immutable typing engine remain the semantic source of truth. A private session store publishes React snapshots every 250 ms and at start/end/reset; an aria-hidden window of up to 288 graphemes is painted via DOM refs in rAF. Chosen over canvas because screen-reader support is already provided by native textarea/target description, while native text selection, font metrics and IME compatibility remain easier to preserve. No measured performance improvement is claimed pending ordinary/profiling browser benchmarks. This decision is reversible if measurements regress.

**ADR-018 (iteration 5, evidence-limited): Do not rewrite the scoring engine to chase browser Event Timing.** In a 500-key CPU×4 diagnostic run, the existing input handler p95 was approximately 0.8 ms, versus keydown Event Timing p95 24 ms from thresholded entries. Browser frame scheduling and page startup are more plausible next profiling targets than speculative changes to immutable scoring/history semantics. The first architecture change reduced profiling commits by over 99% but did not consistently reduce Event Timing p95. No user data or historical v1 scores are migrated by Iteration 5 Phase A.

**ADR-019 (iteration 5 A2, approved engineering budget):** Measure production-typing p95 separately at CPU×1 (≤16ms) and CPU×4 (≤32ms), rather than using the unattained and quantization-affected universal ≤16ms at CPU×4 target. The ×4 budget is a pragmatic frame-budget gate under artificial slowdown; it does not establish exact input-to-presentation timing. Also require per-part Event Timing breakdown, independent next-rAF proxy with variance, and browser trace evidence. All prior unmet targets remain visible.

**ADR-020 (provisional, Home load):** Defer first Dexie module import until local-settings/history hydration, after the first render opportunity. Render a self-hosted static HTML startup shell before React boot. No network fonts exist in this repository, so subset preload is NOT implemented rather than introducing a CDN request. Inline critical CSS is a CSP consideration: future strict CSP must hash the exact style block, and style attributes from theme runtime require separate mitigation. Defer worker initialization: current score worker is already instantiated only on completion, not on Home. LCP/JS improvement requires benchmark evidence.

**ADR-021 (Iteration 5, controlled regression bisect):** On fixed Lighthouse profile 5× at each of eight SHAs and eight targeted source revert variants, `ab8e9d9` introduced ~320ms LCP regression linked to eager→dynamic persistence module imports. The static Home shell alone is not the persistent cause. Restore eager storage facade module import in UiStore while deferring *database access* until Layout's post-first-paint effect, preserving the local-first semantics and old storage contracts. Accept that 105kB initial JS is **not** met by this repair; no misleading single-entry-only savings claim. Source: GH Actions #42035312314 and #42036088912.

**ADR-022:** Five measured Chromium/CDP trials per CPU (run #42039411859) fail ×1 p95≤16ms and fail robust ×4 p95≤32ms (one trial 40ms). EventLatency slices are not associated one-to-one with 500 keystrokes, so a one/two-frame alternative cannot be claimed passed. rAF callback timing is frame-phase dependent, not input-to-photon. Retain original acceptance fail pending better correlation / physical device validation.

**ADR-023 (LCP follow-up, experimental):** Raw Lighthouse `largest-contentful-paint-element` identifies the real Home `<h1>` with ~1502.5ms render delay in a 1955ms LCP sample; `registerSW.js` contributes an estimated 301ms render-blocking opportunity. Disable VitePWA synchronous registration injection and use native service-worker registration only after page load/idle. Keep `sw.js` scope under `import.meta.env.BASE_URL` for GitHub Pages paths. Five-run Lighthouse and offline/upgrade regressions are mandatory before acceptance. No fake pre-rendered heading or nonhydrating shell is admitted into production only to game LCP.

**ADR-024 (LCP measured rejection):** Deferred PWA registration was trialed at SHA `9cc89e0d`, Lighthouse 12.8.2 simulated mobile ×5, median LCP 1952.95ms, CLS 0. Compared with the ~1954ms controlled post-regression repair, this is not meaningful evidence of a faster user-facing paint. Revert ADR-023's experimental implementation to the stable existing VitePWA registration behavior. A render-blocker opportunity estimate is not itself a demonstrated savings.

**ADR-025 (Iteration 5 i18n safety):** Translate Profile, Race and Classroom *presentation strings* through the UI locale only; preserve `locale` on typing assignments, domain entities, scored attempts, backup schema and room seeds. English achievement/bot labels are resolved by stable IDs for display and do not alter persisted identities or simulated race behavior. Emergency/destructive backup confirmations and WebRTC IP/STUN disclosure must be available in the selected UI language. A full native-speaker audit of dynamic copy is still required before declaring 100% RU/EN.

**ADR-026 (Iteration 6 experiment, not yet accepted):** Preserve the authentic checked-in Home HTML, global CSS and all UI content; on initial Home visit perform dynamic import of the normal React bootstrap after two animation frames. Deep-links mount immediately and pre-hydration navigation bypasses delay. The app remains fully interactive once loaded, with no specialized Lighthouse/User-Agent path, content removal, or hiding. Accept this *candidate* only after 10-run matched LCP, full cross-browser E2E, and measured time-to-interactive/network startup. **Static eager entry gzip no longer describes the bytes required to hydrate or interact**; the initial-JS target must count deferred bootstrap bytes downloaded on initial Home as well. Performance acceptance goals are unchanged.

**ADR-027 (Iteration 6 content versioning):** A full 124×2 course audit at #42117417962 found 242/248 four-gram overlap violations because lessons 4–124 reused focus text in practice and review. Keep every existing practice ID and v1 review score; preserve the first three v2 prompts and make distinct review content for lessons 4–124 using new `-review-v3` IDs. Historical `-review` IDs continue to resolve against the original legacy text length. Tighten—not weaken—the content gate from 3 to 124 lessons; no old session is rewritten. Generated early-level content is a **keyboard drill**, not human prose or externally licensed text; advanced review material comprises separately authored scenarios plus drills. Require verified full-corpus and browser CI before acceptance; no credit for new prompts without proof.

**ADR-028 (opt-in performance lab only, not a product switch):** Allow an environment-controlled Preact/compat alias exclusively to compare Preact against normal React with matched Lighthouse 12.8.2 x10, same runner, plus all-browser E2E. The default remains React, no package-lock modification or deployment. Reject Preact if hydration, a11y, scoring, PWA or UI behavior diverges, regardless of small gzip wins. Full *interactive* startup bytes include deferred bootstrap and cannot be replaced with entry-only bytes. No change of acceptance threshold.

**ADR-029 (Iteration 6, native landmarks and stricter source gate):** The skip link and `<main id="main-content">` are now owned by native `index.html` outside React replaceable `#root`/`#chrome-root`. A head-time hash guard suppresses incorrect Home chrome on deep links, and the skip link's capture listener changes focus without changing the hash. Separate main and nav roots hydrate the genuine Home content; this is an architectural candidate, not an LCP/a11y pass until validated by hydration-identity E2E, all-browser focus ×5 and matched Lighthouse ×10. The Stage7 source assertion formerly required `e.preventDefault()` and `links.map` in `Layout.tsx` specifically; that was an implementation-location assumption, not an accessibility acceptance criterion. It has been **strengthened** to verify native skip and main positions, focus activation, deep-link guard, separate real hydration roots, operational nav and no React-created main/skip. No performance/axe/coverage thresholds or tests are disabled. A failed E2E or median LCP regression still rejects the candidate.

**ADR-029a (native deep-link focus correction):** Stress run #42223072837 (89/90) disproved hiding all `.app` during deep-link loading: the native `<main>` became unfocusable even though skip-link itself persisted. Correct the CSS guard to hide **only the two stale React roots** `#root` and `#chrome-root`; leave `<main>` focusable from first paint. This is a stricter accessibility invariant, not a test exclusion or LCP special case. Original failing E2E remains mandatory, as do full 90-case cross-browser ×5, axe, quality and Lighthouse. Candidate pending verification.

**ADR-030 (Iteration 6, one route authority across split roots):** The first native-shell candidate had two independent React Router `HashRouter` trees. Original unmodified E2E Home→Practice failed in all three browsers because programmatic NavLink history changes in Chrome were not broadcast to the main router; stable native focus x5 separately passed 90/90. Correct the architecture, not the test: keep `HashRouter` only around the main content root, render Chrome as normal anchor links with true hashchange, and mirror main-router Link navigation via a `tykora:route-changed` event for active-link display. No private navigation/score state changes, no thresholds altered. Require CI and full a11y replay before accepting.

**ADR-031 (Iteration 6, reject opt-in Preact as current production choice):** Same-runner Lighthouse12.8.2 mobile N10 at [#42226025567](https://github.com/markofornoliak/tykora/actions/runs/42226025567) observed React full interactive gzip152,969B/TBT84.25ms/Performance100 vs opt-in Preact92,899B/TBT99.5ms/Performance99; Preact passed 186 all-browser E2E +9 offline PWA, but React Profiler is emulated as no-op in the lab. **Do not ship** merely for −39.27% JS: the strictly required TBT and Performance goals regressed, and profiling equivalence remains unproven. No downgrade of performance thresholds, no change to default React, no publish. Revisit only with measured TBT/Profiler parity, not subjective preference. Full raw chunks/source groups in `docs/ITER6-JS-LEDGER.md`.
